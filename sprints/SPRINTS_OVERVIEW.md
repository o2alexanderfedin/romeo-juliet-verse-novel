## Sprint Framework Philosophy

### Task-Based Approach
- **Granular Tasks**: Each stanza or small group of stanzas = one task
- **Clear Objectives**: Every task has specific deliverables
- **Quality Gates**: Must pass criteria before proceeding
- **Iterative**: Build incrementally, verify constantly

### Reference-Based (Not Duplicative)
- **Tasks reference planning docs**: Via URLs, not copy-paste
- **Avoids duplication**: Single source of truth in planning/
- **Stays current**: If planning changes, tasks reference updated content
- **Cleaner structure**: Tasks focus on process, planning focuses on content

### Progressive Complexity
- **Sprint 01**: Foundation skills (no novel composition)
- **Sprint 02-05**: Chapter 1 composition (55 stanzas)
- **Sprint 06**: Chapter 1 revision
- **[Future sprints]**: Repeat pattern for Chapters 2-8

## How to Use This Sprint System

### Phase 1: Preparation (Sprint 01 ONLY)

**MANDATORY FIRST STEP**: Complete Sprint 01 before any novel composition.

**Process**:
1. Start with sprint-01-technical-mastery/README.md
2. Complete tasks 01-09 in sequence
3. Pass technical readiness assessment (task-09)
4. Only proceed to Sprint 02 if assessment = READY (✅)

**Timeline**: 2-3 weeks minimum

**Why Mandatory**:
- 400 stanzas requires solid technical foundation
- Mistakes in 100+ stanzas = massive revision work
- Better to practice 2 weeks than revise 2 months
- Foundation determines success or failure

---

### Phase 2: Composition (Sprint 02+)

**After Sprint 01 Complete and READY**:

#### For Each Sprint:
1. **Read Sprint README.md** - Understand scope, objectives, context
2. **Review Planning References** - Check chapter plan, narrator voice, etc.
3. **Work Through Tasks Sequentially** - Don't skip tasks
4. **Complete Each Task Fully** - Meet all acceptance criteria
5. **Pass Quality Gates** - Don't proceed if quality insufficient
6. **Document Progress** - Track time, lessons learned

#### For Each Task:
1. **Read Task Completely** - Understand objective and process
2. **Review Planning References** - Click URLs, read relevant sections
3. **Follow Task Steps** - Use provided workflow
4. **Meet Acceptance Criteria** - Check all boxes
5. **Produce Output** - Create specified files/documents
6. **Self-Assess** - Honest evaluation of quality
7. **Only Then Proceed** - To next task

## Quality Standards

### Every Stanza Must:
✅ Perfect Onegin stanza form (aBaBccDDeFFeGG)
✅ Perfect iambic tetrameter (verified stress patterns)
✅ Zero forbidden rhymes (no verbs, no grammatical)
✅ Rich or exact rhyme quality preferred
✅ Natural-sounding Russian
✅ Consistent voice (narrator or character)
✅ Serves narrative or lyrical purpose
✅ Publication-ready quality

**No Compromises**: "Good enough" accumulates over 400 stanzas into mediocrity.

## Workflow Integration

### Daily Workflow Example:

**Morning Session** (2-3 hours):
1. Review yesterday's work (read aloud)
2. Make any final adjustments
3. Begin new stanza task
4. Follow task steps
5. Complete draft

**Afternoon Session** (1-2 hours):
1. Continue stanza work
2. Verification and revision
3. Meet acceptance criteria
4. Document in task file
5. Update progress

**Evening** (Optional, 30 min):
1. Review day's work
2. Read aloud
3. Note lessons learned
4. Plan tomorrow's work

### Weekly Workflow:

**Monday-Thursday**: Compose new stanzas (2-4 per week)
**Friday**: Review week's stanzas, revise as needed
**Saturday-Sunday**: Rest OR study Eugene Onegin, read aloud, plan next week

Never skip Sprint 01. Technical mastery is non-negotiable.

One excellent stanza > five mediocre stanzas. Speed comes with practice.

400 stanzas takes 6-12 months. Marathon, not sprint. Sustainable pace crucial.

## Questions and Clarifications

### "Do I have to follow this exactly?"
**Answer**: Sprint 01 should be followed closely (foundation critical). For composition sprints, you can adapt workflow to your style, but don't skip quality gates or verification.

### "Can I work on multiple stanzas in parallel?"
**Answer**: After Sprint 01, you can draft multiple stanzas before revising all at once, but each must pass acceptance criteria before considering sprint complete.

### "What if I find better approach?"
**Answer**: Excellent! Document it in your workflow. Sprint system is framework, not prison.

### "Can I create remaining sprint tasks myself?"
**Answer**: Yes! Follow the pattern from Sprint 01-02. Create task files with: objective, planning references (URLs), steps, acceptance criteria, verification, output.

### "How do I know when I'm done?"
**Answer**: When all 400 stanzas exist, pass technical verification, maintain voice consistency, and meet publication quality standards. Then: additional revision pass of entire work.
